# Acquire ChatGPT or Codex sessions

Use the MCP server to inspect source evidence, then hand the selected material to `ki acquire import` in the receiving Knowledge Islands repository. The MCP tools never stage KI files, archive source records, or delete source sessions. Use the four discover/list/read/checkpoint operations for the chosen adapter.

For a configured ChatGPT store, call `chatgpt_sessions_discover` to confirm the physical source and count, then `chatgpt_sessions_list` or `chatgpt_sessions_checkpoint` to obtain the content-minimised inventory. Each entry preserves an opaque project and session identity, a source locator and relative path, byte size, modification time, and SHA-256 hash. Use `chatgpt_session_read` with the listed `project_id` and `session_id` for one record. It returns base64 bytes with `application/octet-stream`; decode only for faithful transport or inspection, never assume a ChatGPT export schema or infer conversation text from the `*.data` filename. Keep the checkpoint so a later run can compare identity, hash, and timestamps.

For Codex, call `codex_sessions_discover` with the absolute repository path, then `codex_sessions_list` or `codex_sessions_checkpoint` with the same path. The adapter resolves the physical directory and requires each returned thread's working directory to match it exactly. A parent, child, symlink alias, or another repository does not widen the scope. The checkpoint records root thread identities, provenance, state, archive flag, descendant IDs, and the installed Codex version/protocol fingerprint. Call `codex_session_read` with the repository and a listed `thread_id`; `include_turns` defaults to `true` for acquisition. It returns the app-server thread as JSON, not local `.data` bytes.

In the receiving repository, use `ki acquire import --adapter chatgpt --repo /absolute/receiving/repo` or `ki acquire import --adapter codex --repo /absolute/receiving/repo` for the matching intake route. Add `--dry-run` to validate a run before writing repository files. The ChatGPT importer can additionally use `--capture <path>` or `--output <path>` for its local capture and Knowledge Export Package route. A receiving repository controls routing, review, and acceptance; a returned MCP checkpoint alone is not an imported or accepted record.

If the inventory is empty, verify the store structure or exact repository path in [troubleshooting](troubleshooting.md). Do not broaden the Codex repository selector just to obtain more sessions.
