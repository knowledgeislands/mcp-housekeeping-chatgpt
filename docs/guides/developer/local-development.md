# Develop and verify the combined adapter

Install dependencies with `bun install`. Run `bun run test` for the fixture suite, `bunx tsc --noEmit` for type checking, and `bun run build` for the Node 22+ distribution. `bun run ki:server:mcp:dev` watches the source; `bun run ki:server:mcp:inspect` starts the MCP Inspector. Both can touch configured sources, so use an isolated fixture path and test Codex client when developing rather than pointing either command at real session stores.

The server entry point calls `loadConfig()` once and passes the optional ChatGPT store path into `registerProviderTools()`. The config loader accepts an injected environment object for tests and hydrates package-local environment files only when using the process environment. `registerProviderTools()` always registers Codex tools and adds ChatGPT tools only when a store path is configured. Keep that distinction in registration tests and in user-facing setup instructions.

Tool modules validate MCP inputs and adapt results; source inspection belongs in `src/main/chatgpt/local-store.ts` and `src/main/codex/app-server.ts`. The ChatGPT reader accepts only physical store directories and regular `*.data` records under the expected project/conversation layout, preserving opaque bytes and provenance. The Codex reader asks the app server for active and archived threads and rejects a thread whose working directory differs from the selected physical repository. Keep local-store and app-server fixtures isolated from personal session roots. `src/mcp-server/register.test.ts` verifies both the Codex-only and combined registration cases.

Every registered MCP tool uses the read-only annotation; access gating defaults to `read`. A separate public `./codex` package export also exposes a reviewed deletion helper and CLI. That export is outside MCP registration and has its own review artifact, exact repository, installed-version, and confirmation guards. Do not describe the entire package as read-only or invoke that helper as part of acquisition. The retained boundary review MCP-HC-FND-003 in the retiring `mcp-housekeeping-codex` repository records the unresolved public API policy; this guide describes current behavior without settling it.

After changing tool behavior, update schemas and fixture assertions together, then run `bun run test`, `bunx tsc --noEmit`, and the relevant `ki repo audit` checks. For documentation changes, run the `ki-guides`, `ki-authoring`, and `ki-work-roadmap` audits and `bunx rumdl check README.md docs/guides`. Inspect changed paths before committing; no test should read or mutate the user's real ChatGPT or Codex store.
